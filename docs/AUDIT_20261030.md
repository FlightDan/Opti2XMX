# Independent source audit — 2026-10-30

This record covers an independent functional and security review of the Opti2XMX candidate source. It records source inspection and isolated fixture tests, not publication, physical-device acceptance, or validation in a running game. No game files, real Proton prefixes, user model imports, or installed runtime were modified during this review.

## Findings and changes

| Priority | Concrete failure | Resolution and regression evidence |
| --- | --- | --- |
| P1 | Stable Opti archives previously lacked the same pinned size/SHA-256 enforcement as Opti 10. A substituted mirror response or local archive could reach extraction. | Reviewed the primary implementation of size/SHA-256 enforcement for all three releases, including local hits; unique temporary downloads preserve unrelated legacy partial files. Substitution and corrupt-local-cache tests pass. |
| P1 | A valid archive did not establish the integrity of an already-extracted payload. A `ready.json` receipt and three present files allowed modified core DLL, INI, or optional DLL bytes to be reused. | Added immutable bundled file metadata tied to each archive SHA-256. Every allowed file is checked before warm reuse; corrupt payloads are repaired from the verified local archive with atomic writes. Known optional files absent from that exact release are removed; unrelated files are retained. Synthetic corrupt core/INI/optional cases fail against the historical method and pass after the fix. Verified warm hits still avoid extraction and network access. |
| P2 | Missing canonical dependencies implicitly selected a development-only directory outside the project's runtime data. | Removed implicit discovery. Canonical runtime locations and explicitly configured absolute paths remain supported. The negative fixture fails against the historical method and passes after the fix. |
| P2 | FSR PRE correction used a fixed temporary filename. An interruption or failed replacement could leave that file behind and block later valid compiler output with `FileExistsError`. | Use a unique temporary file in the output directory, atomically replace the output, and clean only that operation's temporary file. A preexisting legacy partial remains untouched. Before the fix, the new suite produced one failure and one error; all three cases pass after the fix. Kernel metadata, profile format, and helper API remain unchanged. |

The extracted-file descriptor was generated by hashing fixed allowlisted members from three locally available archives after verifying their complete archive pins. No extracted DLL was executed. It contains 18 file records for 0.9.4, 11 for 0.7.9, and 15 for Opti 10: 44 records total. `package_plugin.py` explicitly includes the descriptor. New backend integrity errors have English frontend translations.

## Validation performed

The final portable backend run was:

```text
python -B -m unittest -v test_dependencies test_archive_integrity test_download_progress test_download_tls test_runtime_setup test_ini_equivalence test_fsr_cm
Ran 65 tests
OK (skipped=3)
```

There were 62 passes and three explicit platform skips: payload symlink safety, cross-process `fcntl` locking, and Unix permission-bit enforcement. Windows execution does not substitute for these Linux tests.

Regression coverage includes substituted downloads, corrupt prepared local archives, preservation of legacy download partials, exact archive/file metadata binding, required/INI/optional payload corruption, removal of stale known optional files, retention of unrelated cache files, rejected extractor substitution, failed atomic cache replacement, local-only cache misses, cross-manager warm reuse, download progress/error release, runtime staging/config rollback, settings undo with strictly equivalent INI formatting, and FSR compiler temporary-file recovery.

The candidate TypeScript source passed `tsc --noEmit` using an existing pinned compiler and dependency resolution paths, without a node_modules junction. The existing built frontend baseline passed 23 scenario groups covering native menus, remounts, autosave, stale replies, selection, progress reconnect, FSR preparation, local-only sources, active-XMX replacement, partial-install rollback, and pending-launch completion. That behavioral run consumed the existing baseline distribution; it is not represented as a fresh candidate build. The candidate still requires its own frozen dependency installation, build, and harness run.
